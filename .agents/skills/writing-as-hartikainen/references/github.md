# GitHub issues, discussions, and PR descriptions

## Issues and discussions

Use a courteous, collaborative tone. A greeting or context link can orient a community discussion, but neither an opening nor a closing formula is required.

- Describe the user's experience and interpretation in first-person singular. Acknowledge material limits in the investigation without downplaying the observation.
- For a bug report, connect the triggering conditions, expected behavior, and observed behavior. Include reproduction details and an established workaround when they help someone investigate.
- For a feature request, explain the desired outcome and invite discussion where choices remain open. Offer to contribute only when the user has expressed that intent.
- Follow the repository's issue template. Keep lengthy supporting code or reproduction details in a collapsible block when that makes the main argument easier to read.
- Distinguish quoted source text from the user's interpretation. Link related reports when they establish context or a relationship.

## PR descriptions

Read [change-descriptions.md](change-descriptions.md) for content and tone.

- Use a concise imperative title. Prefer the PR as the subject when introducing the change; name the affected component when that is more precise.
- Follow the repository's PR template when present. Otherwise let the material determine whether paragraphs need additional structure.
